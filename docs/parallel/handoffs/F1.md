## 6. Exact acceptance criteria

Each item must be reproducible from a clean commit, with the recorded revision,
tool versions and evidence paths. "Zero rows" means verified by count, not by
absence of an error page.

### 6.1 Tier 1 (local, immediate)

- **`CI-WORKFLOW-INTEGRITY`** — parse `.github/workflows/ci.yml`; assert exactly
  one job per declared purpose, every `uses:` pinned to a 40-hex SHA, top-level
  `permissions` limited to `contents: read`, no `pull_request_target`, no
  `${{ ... }}` expression inside `run:` that carries untrusted text, Node/npm
  pins equal to `engines.node`/`packageManager`, `timeout-minutes` present, and
  the steps include `qa:validate` and `verify:reference`. Fail on a floating tag.
- **`SECRETS-HYGIENE-SCAN`** — scan tracked files and the built output for
  private-key blocks, `postgres://…:…@`, bearer/API token shapes and
  `NEXT_PUBLIC_*` names whose values look secret. Assert `.env` is not tracked
  while `.env.example` is. Report only rule name and path, never the match.
- **`PRIVACY-DISCLOSURE-PARITY`** — for each claim in the FA/EN/AR privacy
  content, assert the corresponding fact in code/config: analytics absent ⇒ the
  "no analytics" statement must exist; listed cookies/local storage equal the
  ones actually written; inquiry field list equals the schema; retention state
  equals "not yet defined" until A3/D6 answers. Fail on a compliance claim with
  no owner approval reference.
- **`A11Y-DOM-CONTRACT`** — over all 27 documents: exactly one `h1`; `html[lang]`
  and `dir` correct per locale; every input has an accessible name; every image
  is `alt`-described or `aria-hidden`; ids unique; no `tabindex` > 0; the skip
  link target exists and precedes the navigation; form errors set
  `aria-invalid`/`aria-describedby` and the result region is a live region.
- **`A11Y-CONTRAST-TOKENS`** — compute contrast from token pairs for normal text
  ≥ 4.5:1, large text ≥ 3:1, focus ring/borders ≥ 3:1, in light and dark. Any
  intentional exception must be listed with the reason and the affected pair.
- **`A11Y-REDUCED-MOTION`** — with `prefers-reduced-motion: reduce`, no
  transition/animation remains except those explicitly allowlisted; no content
  appears only through motion; the reduced-motion branch is asserted statically
  now, and through the browser harness once it can emulate the media feature.
- **`PERF-BUNDLE-BUDGET`** — record per-route gzip JS/CSS and total font bytes
  from the build output; fail when any route exceeds its recorded threshold; the
  thresholds are written into the case definition before the first run.
- **`PG-INQUIRY-HTTP-E2E`** — start the production build on a random loopback
  port with a disposable database; valid submission ⇒ 201, exactly one row,
  opaque reference; same key + same payload ⇒ 200/one row; same key + changed
  payload ⇒ 409/one row; `GET /api/inquiries` ⇒ 405; no PII in the response.
- **`PG-OPERATIONS-RECOVERY`** — migration apply → `--verify` passes; a pending
  migration and a modified checksum are each refused; snapshot restores into an
  empty target with identical counts and Unicode; wrong key/migration mismatch
  fail closed; erasure requires `--apply` + `--confirm-id` and refuses active
  retries; cleanup removes only expired metadata and rolls back on failure.
  Record that this proves **local tooling behaviour only, not retention or
  off-host recovery policy**.
- **`ANALYTICS-001`** — load the 27 documents with analytics configuration unset;
  assert zero requests to any analytics host and no injected script/pixel; the
  check must pass today and fail the moment a tracker appears without approval.

### 6.2 Tier 2/3 (implemented feature, staging or lab)

Use D1 §4.9 `HC-V1`–`HC-V14` as the shared script; each case owns a subset and
records its own evidence:

- **Ingress:** valid envelope → 201 and one row; missing, forged, staled (>30 s)
  and replayed-with-different-digest envelopes → 503/409 and zero new rows;
  client-supplied `x-echo-client-*` headers are stripped; a direct request to
  the app port from outside the host fails; `Origin` is preserved byte-for-byte
  and a cross-site request still reaches the app for its 403.
- **Edge limits:** sustain connections/requests above the configured cap and
  prove shedding while the marketing pages stay available; >32 KiB bodies
  (declared and chunked) rejected before the app; a stalled body closes within
  the read timeout; response bodies never logged or cached for the API.
- **Operator:** a named individual logs in and reads one synthetic record; the
  app credential and an anonymous client are denied; revocation denies on the
  next attempt; stdout shows no PII; an audit entry exists (or the compensating
  control is recorded).
- **Database TLS:** `sslmode=verify-full` succeeds with the CA; a plaintext
  connection and a wrong-CA connection are refused; the app never falls back to
  `require`; the DSN never appears in output.
- **Retention/purge:** dry-run lists exactly the policy-eligible rows and deletes
  nothing; applied run deletes those and no others; a row inside the retention
  window survives; exports past expiry are removed; replay/network TTL tables
  still behave. No policy ⇒ the case is BLOCKED, never PASS.
- **Backup/restore drill:** restore into a fresh instance from the approved
  provider mechanism; row counts and Unicode match; migrations verify; grants
  reapplied; measured restore time reported against the approved RTO; wrong key
  fails closed; the erasure manifest is applied before intake reopens.
- **Logs and alerts:** submit synthetic PII, then assert app/edge/DB logs contain
  request id, code and status only; trigger each alert class once and record who
  received it; retention and access for those logs are documented.
- **Artifact/rollback:** the running deployment reports the approved digest;
  roll back to the previous digest, verify health, smoke and migration
  compatibility, and record the rollback point.
- **Performance lab (`PERF-LAB-LIGHTHOUSE`):** run the roadmap's lab Lighthouse
  check (ECHO-602 acceptance, ≥ 90) on the same revision, on the owner-side
  browser through the loopback tunnel or an approved equivalent, and record the
  device class, throttling, build mode and per-route scores. A run with unstated
  conditions is not evidence; a score below target is a finding, not a reason to
  change the tool's settings.

### 6.3 Analytics

Follow H1 §11.3's nine bullets plus H1 §5.4's six implementation rules. The
authoritative conversion is the server-side `inquiry_submitted` emitted only
when `replayed === false`; a client-side conversion event is not accepted. The
count is a **lower bound** and reconciliation may only explain a deficit, never
inflate events. Confirmed-write, replay, outage and PII cases are automated and
must run against the integrated staging revision; disclosure and consent remain
human/legal decisions that no technical PASS can satisfy.

### 6.4 Manual

Every manual PASS needs a reviewer identity and role, the exact revision, the
browser/AT/OS versions, and at least one durable evidence path under
`qa/evidence/<TEST-ID>/` once F1-W4/W8 are fixed. A narrow viewport or a
simulated screen reader is not a substitute for the required capability; the
honest outcome is BLOCKED with a blocker string.

## 7. Revalidation order

Order is chosen to remove false status first, then to add evidence that cannot
be invalidated by late content work, then to spend human and infrastructure
resources once.

1. **Coordinator applies §2.2 fixes** and re-runs `qa:validate`. Expect status
   changes only where a definition edit invalidates a record (the seven watch
   lists, the two manual watches, `evidenceRequired`, the `postgres` suite).
   Because `qa/lib/status.ts:13-15` compares the stored definition hash, the
   seven PASS records whose test object changes will read **STALE**, not PASS,
   until step 2 re-runs them — that is the intended effect of the fix, not a
   regression, and the report should say so rather than quoting a suddenly worse
   headline. BLOCKED records are returned before the freshness check
   (`qa/lib/status.ts:110-115`), so `MANUAL-FIREFOX-GLASS` stays BLOCKED.
   Record the new definition hashes; do not reinterpret old records.
2. **Re-run only what the fixes invalidated, at one clean commit:**
   `LINT`, `TYPECHECK`, `UNIT-SUITE`, `BUILD`, `HTTP-SMOKE`,
   `REFERENCE-INTEGRITY`, `HARNESS-EVIDENCE-METADATA` (their definition hash
   changes when the inherited watch becomes explicit), then the `PG-*` group from
   step 3. `TYPOGRAPHY-*`, `SEO-*`, `BROWSER-404-EXPERIENCE` and
   `SEO-404-HTTP` are current by watch rules and need no re-run until their
   watched paths move; do not re-run them "for completeness" and thereby create
   avoidable dirty-tree risk. Commit the result lines.
3. **Database evidence:** `PG-INQUIRY-INTEGRATION` (fixed prerequisite),
   `PG-INQUIRY-HTTP-E2E`, `PG-OPERATIONS-RECOVERY`. This converts the single
   release-critical NOT_RUN into real evidence — the highest-value single step
   available today.
4. **New Tier 1 automation** (`CI-WORKFLOW-INTEGRITY`, `SECRETS-HYGIENE-SCAN`,
   `PRIVACY-DISCLOSURE-PARITY`, `A11Y-DOM-CONTRACT`, `A11Y-CONTRAST-TOKENS`,
   `A11Y-REDUCED-MOTION`, `PERF-BUNDLE-BUDGET`, `ANALYTICS-001`). Triage defects
   into B/D2 work with severity; do not "fix" the test to make it pass.
5. **Browser matrices only at a content freeze.** `BROWSER-RTL-MATRIX`,
   `BROWSER-LOCALE-SWITCH`, `BROWSER-VISUAL-CORRECTIONS`,
   `BROWSER-TYPOGRAPHY-MATRIX` watch `src/**`, so they will be STALE again after
   the next content commit. Re-run them once B2/C5 are integrated and the
   candidate is frozen; that is also when the four stale records can be
   superseded honestly.
6. **Human acceptance (F2b) after that freeze:** keyboard/SR, 200 % zoom,
   cross-engine, Firefox glass, native FA/AR, forced colors — with named humans,
   durable evidence and owner/legal roles where gated.
7. **Staging suite (F3) once E2 exists:** ingress, edge limits, operator, DB TLS,
   log redaction, health, shutdown, retention, erasure manifest, backup drill,
   monitoring, artifact identity, rollback, smoke, plus the owner-side lab

   migrations; never point these at production data.
8. **Analytics verification (H4) once H2/H3 land:** `ANALYTICS-002`–`013`, then

Rules that apply at every step: run on a clean tree, commit results afterwards,
never delete a failed or stale record, never record a PASS that was not
executed, and never use `--role owner`/`--role legal` on someone else's behalf.
