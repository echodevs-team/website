## Delivered behavior

`scripts/inquiry-ops.mjs`: local Unix-socket-only `list`, `show`, single-ID `delete`, bounded encrypted `backup`/empty-target `restore`, and private backup `keygen`. No endpoint, dashboard, status-update workflow, notification service or new dependency. Application tables/migrations **001/002 remain unchanged**; no customer data migration or automatic inquiry purge.

Readback requires dedicated environment credentials, effective approved capability membership, explicit PII acknowledgement and a private non-overwritten output file. It refuses owner/superuser/app credentials, remote TCP, shared/symlink output paths and unbounded filters. Metadata pages default to `new`, max 50, microsecond-safe keyset cursors; details require an opaque reference. JSON escapes terminal and bidi controls; stdout/stderr never contains payloads/SQL/credentials. Separate erasure privilege cannot read contacts; dry run is default, apply requires exact confirmation and refuses active replay keys.

Capability provisioning creates four **NOLOGIN groups** only, not human identities/memberships. App SQL permissions remain scoped. Generated `app.env` no longer contains the migration-owner URL; `owner.env` is separate. This reduces accidental credential mixing, but the existing same-OS-user private trust owner is still a **development** convenience, not production human isolation.

Backup snapshot is repeatable-read, encrypted/authenticated AES-256-GCM, 0600 exclusive output, migration-compatible and capped at 1,000 rows/table and 16 MiB. Restore locks before snapshot reads, requires an explicitly named empty migrated target, has no DROP/TRUNCATE capability, and rolls back on later constraint errors. It includes replay/counter state but not passwords/HMAC secrets/roles/configuration. This is a local application-data snapshot/rehearsal, not native PG/PITR/HA production backup readiness.

Migrations gain read-only `--verify` and unknown-history rejection. Temporary-state cleanup is now atomic across both TTL tables, with rollback/no success counts on permission failure. No business retention period or age deletion exists. Restore requires approved reconciliation of erased records/exports/backup policy before real intake.
